# CLAUDE.md

## What this is
OneTrip is a mobile-first PWA that stops drivers from "pencil whipping" pre-trip truck inspections — it forces a live-camera, phased checklist walkthrough and backs every certified inspection up to a company-controlled Google Drive.

This folder holds two of the system's parts, `onetrip-driver/` and `onetrip-drive-function/`, described below. The other two OneTrip apps live elsewhere: the admin dashboard (`C:\Users\dvwii\OneDrive\Desktop\4_Resources\AI Skills and such\onetrip-admin\`, repo `one-trip-admin` with a hyphen) and the mechanic portal (`C:\Users\dvwii\onetrip-mechanic\`). `PROGRESS.md` in this same folder is the full project history and state for all of them; read it before starting work. Other folders here (e.g. `job-mode/`) are unrelated projects.

## Tech stack

**`onetrip-driver/`** — the driver-facing app, public repo `onetripapp/onetrip-driver`, deployed as a static site via GitHub Pages on push to `main`
- Plain HTML/CSS/vanilla JavaScript. **No framework, no build step, no bundler, no npm dependencies, no TypeScript** (no `package.json` even exists in this directory) — script tags in `index.html` load global functions in order, and that's the entire pipeline.
- Rendering: hand-rolled `el()` DOM-builder in `js/app.js`, full teardown-and-rebuild via `render()`, which always defers to the next animation frame. **One exception**: Pass/Fail/N/A taps go through `updateAfterToggleTap()`, which patches only the affected elements. The full-render functions and that targeted update are marked "KEEP IN SYNC". Change what a toggle looks like in both places or neither.
- Persistence: `localStorage` for inspection state (`js/state.js`), `IndexedDB` for photo blobs (`js/photoStore.js`).
- Styling: plain CSS, no preprocessor, no CSS-in-JS — see Conventions below.
- `sw.js` is a hand-written service worker (cache-first app shell), not generated by any tool. Read its version-history header before touching it.

**`onetrip-drive-function/`** — the Drive backend (uploads, plus the `checkResolutions`/`acknowledgeResolutions` actions)
- Single Node.js file (`index.js`), ES modules (`"type": "module"`), deployed as a Google Cloud Run function (2nd-gen "Cloud Functions"). Entry point `uploadinspectionfile` (all lowercase).
- Dependencies: `@google-cloud/functions-framework` (the `http()` handler registration) and `googleapis` (Drive API v3 client). That's the entire dependency list.
- No database anywhere in this project. Google Drive itself is the only persistent store (photos + `inspection-data.json` + `inspection-summary.txt` per inspection folder). Credentials live in Google Secret Manager, not in code.
- Deployed by pasting `index.js` into the Cloud Run console's Source tab. It's a **local git repo with no remote** (since 2026-10-11): git is history only and never deploys anything. Commit after each console deploy so the log matches what's live.

## Project rules
- **Always write complete file contents.** Never truncate, never use placeholder comments like `// rest stays the same` or `// ... existing code ...` — every file you touch should be fully written out, every time.
- **Always state the file path before making a change or running a command**, so it's clear up front what's about to be touched.
- **Always explain what a change does in plain terms**, before or after making it — assume the person reading may not read the diff line-by-line.
- **Ask before every `git push` and every Cloud Run console deploy**, even small follow-ups.
- **Never run `git config`**, not even to read a value, and not even with permission.
- **Bump `CACHE_NAME` in `onetrip-driver/sw.js` on every deploy that changes any `SHELL_FILES` entry**, including comment-only changes. Then verify the live file content with a cache-busting fetch, not just that the push succeeded.
- **Test against `TEST001`** (or another obviously fake truck), never `826016`, which is a real truck with real Drive records.
- **Never ask for, guess, or commit secrets**: not the passcode, OAuth client secrets, refresh tokens, or the app shared secret's value. To get past the passcode gate in a test browser, set its `localStorage` flag.
- **Policy and compliance calls belong to the user** (OOS/MECH classification, what blocks a truck). Ask; don't invent.

## Conventions
- **File organization**: `onetrip-driver/js/` is split by concern, not by screen — `data.js` (static station/zone definitions and `KNOWN_TRUCKS`), `state.js` (the `inspection` object + persistence + derived-data helpers + export builders), `app.js` (all rendering + event wiring), `drive.js` (backend calls: upload and resolution check/acknowledge), `auth.js` (passcode gate), `photoStore.js` (IndexedDB), `baselineReference.js` (reference-photo lookup). Keep new code in the file matching its concern rather than creating new files per feature.
- **Naming**: `camelCase` for functions/variables, `kebab-case` for CSS classes, station/sub-item IDs are short lowercase codes matching the physical inspection zones (`'1-door'`, `'3b'`, `'11-air-build-rate'`) — defined once in `data.js` and referenced everywhere else by that ID, never re-derived.
- **Styling (driver app)**: every color, font, radius, and tap-target size is a CSS variable defined once in `css/tokens.css` — no literal hex codes, no hardcoded `border-radius`, no hardcoded `font-family` anywhere else. If a new value is needed, add a token first, then reference it. Square corners (2px radius) everywhere, no box-shadows, no gradients, no pill/badge shapes, no green, no emoji in the app's own UI. `--accent` (muted gold) is reserved for the three uses listed in `tokens.css`, and only two exist today: the progress-bar fill and the Summary screen's open-defect count. The third, a day-streak number, isn't built. Individual Fail toggles stay neutral ink. No parent-company name or branding in the UI, only the OneTrip wordmark and shield mark. (The admin and mechanic apps use their own charcoal/brass token sets, and admin uses green for resolved defects. These rules are the driver app's.)
- **Comments**: sparse, and only to explain *why* something non-obvious is done a certain way (a browser quirk worked around, a deliberate product decision, a gotcha that cost real debugging time) — not to restate what the code already says.
- **Functions are global**, not modules — every `.js` file in `onetrip-driver` shares one global scope via plain `<script>` tags. Don't introduce `import`/`export` or IIFEs there; that's only used in the separate `onetrip-drive-function` backend, which is genuinely a Node/ESM environment.
- **Commits** end with a `Co-Authored-By:` trailer naming the Claude model doing the work.
